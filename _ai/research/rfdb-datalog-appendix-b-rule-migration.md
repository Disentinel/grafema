### G1 — Stratified negation (anti-join over frozen lower stratum)

## Stays-top-down rationale

**None.** All 51 rules are classified `rule-portable` — every one is non-recursive (or uses only stratified derived helpers), has no `path()`/transitive-closure clause, and uses negation only over strictly-lower (frozen) strata. There is no rule in the current corpus that requires the top-down evaluator.

The candidates one might expect to stay top-down, and why they do **not**:

- **`beam-state-init-only-gate`, `beam-handler-unguarded-tick`** — use derived helper predicates (`handler_writes`, `has_guard`) and negate them. This is *not* recursion: the helper is a strictly-lower stratum the SCC stratifier (§4) places below the negating rule, with the negation reading the frozen helper relation. Fully bottom-up via stratified semi-naive evaluation.
- **`beam-handler-self-loop-sends`, `beam-handler-self-loop-publishes`** — contain a cyclic *pattern* (M→C→M) but it is a **fixed-length** two-edge self-join, not a closure/`path()`. A finite positive multi-way join is bottom-up materializable; no fixpoint over an unbounded path is needed.
- **Multi-clause orphan packs** (`*-nodes-orphan`) — disjunction across sibling seed clauses, not mutual recursion. Each clause seeds the same single-stratum IDB predicate.

Because the corpus is 100% portable, Gate A coding can target the bottom-up engine exclusively; the top-down evaluator is not on the critical path for any production rule.
