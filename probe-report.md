## 5. Grafema CLI

| Пункт | Статус | Детали |
|---|---|---|
| Каноничный пакет | `@grafema/cli` | `npm install grafema` ставит мета-пакет `grafema`, чей bin — симлинк на `@grafema/cli/dist/cli.js`. Оба `latest = 0.3.29`. Канонична как раз связка: ставится `grafema`, бинарь — из `@grafema/cli` |
| `npm install grafema` | ✅ **33 c** | 136 пакетов, 0 уязвимостей. Нативные бинари приезжают через optionalDependency `@grafema/grafema-linux-x64` |
| `grafema analyze` | ⚠️ **частично** | `--quickstart` создал конфиг; RFDB-сервер (v0.3.28) и orchestrator (0.1.0) стартуют, структурные узлы коммитятся (**6 узлов**). НО JS-анализатор падает: `Failed to create JS analyzer pool for streaming: failed to spawn worker 0` → **0 семантических узлов/рёбер** |

**Причина деградации analyze:** нативный npm-пакет `@grafema/grafema-linux-x64/bin/` содержит только `grafema-orchestrator` и `rfdb-server`. Бинарь `grafema-analyzer` (Haskell), который orchestrator пытается заспавнить воркером, **в npm-дистрибутиве отсутствует**, а Haskell-тулчейна для сборки в окружении нет. Итог: из коробки `npm install grafema` даёт рабочие RFDB + orchestrator + структурный граф, но **семантический анализ JS не работает**.

Время: install 33 c, analyze 0.03 c (падает мгновенно на спавне воркера).

## Рекомендация: что может жить в этом окружении, а что требует VPS

> `SESSION_PROTOCOL.md` в репозитории **отсутствует** (искал по всему дереву). Маппинг ниже выведен из наблюдаемых возможностей, а не из текста протокола — при появлении файла стоит сверить.

### ✅ Может жить в cloud (этом окружении)
- **Работа со знанием и памятью** — Enox (recall/remember/query), долговременная память доступна и персистентна.
- **Linear-триаж и оркестрация задач** — list/get/save через MCP.
- **GitHub-операции через MCP** — ревью PR, комменты, чтение CI, ведение веток (кроме main как safety-net).
- **Редактирование кода и сборки** — node/npm, rust/cargo, python; задачи на JS/TS/Rust/Python.
- **Всё, что упирается только в `registry.npmjs.org`** — npm-инсталляции, публикация (с осторожностью).

### 🖥️ Требует VPS (или более широкого окружения)
- **Любая проверка `*.grafema.dev` / `enox.dev`** — домены вне allowlist. Сюда попадает **воспроизведение MKT-54** (статус `/blog/`), smoke-тесты лендинга и atlas. Из cloud это в принципе недостижимо.
- **Полный семантический анализ Grafema** — нужен бинарь `grafema-analyzer` (Haskell) либо Haskell-тулчейн; в npm-дистрибутиве его нет, тулчейна тоже. Из коробки только структурный граф.
- **Долгоживущие демоны/сервисы с состоянием** — контейнер эфемерный, между прогонами диск не переживает.
- **Любая задача, опирающаяся на защиту main как инвариант** — здесь push в main на уровне прокси не блокируется.

### Открытые вопросы / флаги
1. **Инвариант push-в-main не подтверждён** — нужно либо включить branch protection на GitHub, либо запрет на git-прокси.
2. **`grafema analyze` из npm не делает семантику** — если cloud-агентам нужен граф, надо либо паблишить `grafema-analyzer` в npm-нативный пакет, либо собирать его в setup-скрипте окружения.
3. **`MKT-57` отсутствует** — отчёт сохранён файлом; в Linear не публиковался (задача запрещала создание issue).
