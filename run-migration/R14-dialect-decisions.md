То есть из всего лейна для «boot.rofl транслируется» нужны **целые константы**, **`is`** и **`+`**.

самостоятельный шаг нельзя.

## Решения

### 1. Целая константа — `translate-as-is` (17 кейсов)

Текущий отказ ссылается на `rfdb_server.rs:3205-3210` и утверждает, что «all-digit strings re-type
to Value::Id». Ссылка **протухла**: строки 3205-3210 в
`packages/rfdb-server/src/bin/rfdb_server.rs` — это doc-комментарий `wire_string_to_value`, и он
говорит ровно обратное:

```
3207: /// grammar and the rule that resolves the bare-decimal ambiguity (a bare decimal is a node
3208: /// id; every other variant is tagged; a `Str` is escaped only when the verbatim form would
3209: /// be re-read as something else). Untagged input keeps its legacy reading, so clients that
```

Типизированный числовой литерал приходит не через `Value::from_term_const`
(`packages/rfdb-server/src/datalog/eval.rs:120-128` прямо это оговаривает), а через `Term::Lit`, и
на проводе получает тег. Прогон:

```
| xout(K, V) :- p(K, V).
| p("k_int", 1). p("k_quoted", "1"). p("k_float", 1.5). p("k_neg", -7). p("k_big", 295147905179352825856).
-> {"K":"k_big","V":"~big:295147905179352825856"}
-> {"K":"k_float","V":"~float:1.5"}
-> {"V":"~int:1","K":"k_int"}
-> {"V":"~int:-7","K":"k_neg"}
-> {"V":"1","K":"k_quoted"}
```

`1` и `"1"` — разные значения, отличимые на проводе (`~int:1` против `1`). Как фильтр в теле тоже
различает:

```
| q(K) :- p(K, 1).
| p("k_int", 1). p("k_quoted", "1").
-> {"K":"k_int"}
```

Это ровно то, чего требует v0, где три домена не унифицируются между собой
(`vendor/rofl-v0/src/unify.ts:54-56`, `vendor/rofl-v0/src/parser.ts:103-108`):

```
| n(7). n(-7). n("7"). n(seven).
? n(X) -> ["X = \"7\"","X = -7","X = 7","X = seven"]
factKeys(n) = ["n[main](\"7\")","n[main](-7)","n[main](7)","n[main](seven)"]
```

Отрицательные литералы (`parser.ts:104-108`) движок принимает и как факт, и как границу фильтра:

```
| xc(X) :- u_p(X), gte(X, -2), lte(X, 2).
| u_p(1). u_p(-7). u_p(-2). u_p(3).
-> {"X":"~int:-2"}
-> {"X":"~int:1"}
```

**Что осталось сделать в харнессе:** декодер обратного направления. Сейчас
`packages/rofl-conformance/src/adapter.ts:190` переатомизирует каждый кортеж
(`mkf('$t', tuple.map((a) => mka(a)))`), а слова `~int:`, `~float:`, `~big:`, `~str:`, `~term:` не
встречаются в `packages/rofl-conformance/src/*.ts` ни разу (grep — 0 совпадений). Пока декодера нет,
целое вернётся в v0-мир как атом `~int:7`. Это работа на стороне харнесса, не движка.

Границы `i64` / 2^53 уже отсечены отдельным кодом `missing:bignum` (`translate.ts:117-118`) — и это
правильно, потому что v0 молча теряет точность:

```
| p(9007199254740993).
? p(X) -> ["X = 9007199254740992"]
```

### 2. Целое внутри билтина — `translate-as-is` (17 кейсов)

Отдельного механизма не требует: как только целое стало `Value::Int`, `gte`/`lte`/`lt`/`gt`
сравнивают его точно, включая отрицательные (прогон выше) и включая случай, когда обе стороны —
переменные из одного литерала:

```
| xg(X, Y) :- u_e(X, Y), lt(X, Y).
| u_e(1, 2). u_e(2, 1). u_e(3, 3).
-> {"X":"~int:1","Y":"~int:2"}
```

### 3. `!=`, `<`, `<=`, `>`, `>=` — `translate-as-is`, но с предусловием (4 + 2 + 5 + 0 + 5 кейсов)

В RFDB это `neq`, `lt`, `lte`, `gt`, `gte` — все пять зарегистрированы в
`packages/rfdb-server/src/derive/builtin.rs:1358` (`registry()`, «the sole registration point»).
Семантика совпадает с v0 **в пределах одного домена**:

- на атомах `lt` не срабатывает — как и в v0 (`u_e("a","b")` → 0 rows; v0: `both(X, Y)` пусто на
  атомах);
- `neq` на строках работает (`u_e("a","b")` → одна строка, `u_e("a","a")` — нет).

Два расхождения, оба лечатся кодировкой из пункта 4:

**(а)** `neq` схлопывает домены: `bound_str` (`builtin.rs:341-343`) приводит аргумент через
`Value::as_str`, поэтому

```
| xd(X, Y) :- u_e(X, Y), neq(X, Y).
| u_e(1, "1").
-> 0 rows
```

тогда как v0 считает их разными:

```
| p(1). p("1"). p(one).
| d(X, Y) :- p(X), p(Y), X != Y.
? d(X, Y) -> ["X = \"1\", Y = 1","X = \"1\", Y = one","X = 1, Y = \"1\"","X = 1, Y = one","X = one, Y = \"1\"","X = one, Y = 1"]
```

**(б)** сравнение числовое там, где v0 отказывает:

```
| xg(X, Y) :- u_e(X, Y), lt(X, Y).
| u_e("7", "42").
-> {"Y":"42","X":"7"}
```

а v0 на тех же данных даёт пусто, потому что `"7"` — строка, а не целое
(`vendor/rofl-v0/src/unify.ts:96-113`, `evalArith` возвращает `null` на не-`i`):

```
| p("7"). p("42").
| g(X, Y) :- p(X), p(Y), X < Y.
? g(X, Y) -> []
```

Оба лечатся тегом `s:` (пункт 4) и обе починки проверены — см. R5-B и R5-C ниже.

Оператор `>` в сьюте не встречается ни разу, но он есть в `CMP_OPS` (`parser.ts:76`) и работает:

```
| p(1). p(2).
| g(X) :- p(X), X > 1.
? g(X) -> ["X = 2"]
```

**Опасность, которую надо зафиксировать отдельно:** незарегистрированное имя билтина RFDB не считает
ошибкой — оно молча даёт пустое отношение.

```
| xm(X, Y) :- u_n(X), add(X, 1, Y).
| u_n(7).
-> 0 rows
```

То есть транслятор не имеет права выпускать имя, которого нет в `registry()`: получится не отказ, а
тихо неверный ответ.

### 4. Строковая константа — `translate-with-rewrite` (0 кейсов, но обязателен)

v0 держит `p("hello")` и `p(hello)` как два разных факта:

```
| p("hello"). p(hello).
? p(X) -> ["X = \"hello\"","X = hello"]
factKeys(p) = ["p[main](\"hello\")","p[main](hello)"]
```

а RFDB на текущей кодировке (`translate.ts:301-309` рендерит атом как `"имя"`) вернёт для обоих
`hello` — что и написано в тексте отказа. Верно.

**Переписывание:** атом — как есть; строка v0 — с префиксом `s:`. Тегировать атомы не нужно и
незачем: токенайзер v0 (`parser.ts:59-65`) допускает в идентификаторе только `[A-Za-z0-9_]`, так что
атома с двоеточием не бывает, а значит `s:` — инъективный тег без экранирования. Прогон итоговой
кодировки, все четыре домена v0 в одном отношении:

```
| xq(X) :- u_n(X).
| u_n(seven). u_n("s:7"). u_n(7). u_n(-7). u_n("s:seven"). u_n("s:s:x"). u_n("s:~int:7").
-> {"X":"s:7"}
-> {"X":"s:s:x"}
-> {"X":"s:seven"}
-> {"X":"s:~int:7"}
-> {"X":"seven"}
-> {"X":"~int:-7"}
-> {"X":"~int:7"}
```

Семь фактов — семь различимых значений, обратное отображение однозначно. Строка v0, похожая на
служебный тег, тоже не ломается: `"~int:7"` уезжает как `s:~int:7` и возвращается строкой.

Эта же кодировка чинит оба расхождения из пункта 3 — сравнение перестаёт быть числовым:

```
| xg(X, Y) :- u_e(X, Y), lt(X, Y).
| u_e(1, 2). u_e(2, 1). u_e("s:7", "s:42"). u_e(a, b). u_e(-7, 0).
-> {"Y":"~int:0","X":"~int:-7"}
-> {"Y":"~int:2","X":"~int:1"}
```

и `neq` перестаёт схлопывать домены — ровно шесть строк, ровно как v0 в примере выше:

```
| xd(X, Y) :- u_e(X, Y), neq(X, Y).
| u_e(1, "s:1"). u_e("s:1", 1). u_e(1, one). u_e(one, 1). u_e("s:1", one). u_e(one, "s:1"). u_e(1, 1). u_e(one, one).
-> {"Y":"s:1","X":"one"}
-> {"X":"one","Y":"~int:1"}
-> {"Y":"one","X":"s:1"}
-> {"X":"s:1","Y":"~int:1"}
-> {"Y":"one","X":"~int:1"}
-> {"X":"~int:1","Y":"s:1"}
```

Строка и функтор внутри билтина (`D6`, `D7`) после этого решаются сами собой: v0 на них просто
проваливает посылку, без ошибки —

```
| p("7").
| g(X) :- p(X), X < 42.
| s(X, Y) :- p(X), Y is X + 1.
? g(X)    -> []
? s(X, Y) -> []
```

```
| p(cons(a, nil)). p(nil).
| d(X) :- p(X), X != nil.
| s(X, Y) :- p(X), Y is X + 1.
? d(X)    -> ["X = cons(a,nil)"]
? s(X, Y) -> []
```

— и RFDB с `s:`-тегом ведёт себя так же (`lt` на `s:`-строках даёт 0 rows, `neq` работает).
Функторный аргумент до билтина всё равно не доедет: он отсекается раньше кодом
`missing:compound-terms` (`translate.ts:112-114`).

### 5. `is` и арифметика `+ - * / mod` — `extend-rfdb` (17 / 16 / 5 / 1 / 0 / 0 кейсов)

Арифметики в RFDB нет **никакой**. Проверено пять имён и инфиксная форма:

```
| m(X, Y) :- n(X), add(X, 1, Y).    -> 0 rows
| m(X, Y) :- n(X), plus(X, 1, Y).   -> 0 rows
| m(X, Y) :- n(X), sum(X, 1, Y).    -> 0 rows
| m(X, Y) :- n(X), is(Y, X).        -> 0 rows
| m(X, Y) :- n(X), Y is X + 1.      -> !! Datalog parse error: Parse error at 8: unexpected input after query
```

В `registry()` (`packages/rfdb-server/src/derive/builtin.rs:1358-1568`) ровно 29 имён, ни одного
арифметического: `node, type, edge,
incoming, attr, neq, gt, lt, gte, lte, starts_with, not_starts_with, string_contains, method_suffix,
ends_with, concat, str_lower, basename, strip_quotes, strip_prefix, strip_suffix, last_segment,
first_segment, replace_all, path_resolve, split, relative_import_resolve, edge_attr, node_attr`.

**Почему это «расширить движок», а не «месяцы работы».** Механизм билтина, который **производит**
значение, уже есть и уже гибок по режиму. `concat/3` в свободном режиме производит:

```
| m(X, Y) :- n(X), concat(X, "!", Y).
| n("a"). n("b").
-> {"X":"a","Y":"a!"}
-> {"Y":"b!","X":"b"}
```

в связанном — работает фильтром:

```
| xm(X) :- u_n(X), concat(X, "!", "a!").
| u_n("a"). u_n("b").
-> {"X":"a"}
```

и его выход годится как ключ джойна ниже по телу:

```
| xm(X, Z) :- u_n(X), concat(X, "!", Y), u_t(Y, Z).
| u_n("a"). u_t("a!", "hit").
-> {"Z":"hit","X":"a"}
```

Значит, нужна **регистрация в существующем реестре** (`registry()` — «the sole registration point,
spec §7»), а не новый механизм в планировщике.

**Что именно надо повторить.** Полная семантика v0 снята одним прогоном
(`vendor/rofl-v0/src/unify.ts:96-113`, `ARITH_OPS` на `unify.ts:115`, грамматика — `parser.ts:129-157`):

```
| n(7). n(10). n(-7). n(0).
| plus(X, Y)  :- n(X), Y is X + 1.
| minus(X, Y) :- n(X), Y is 0 - X.
| times(X, Y) :- n(X), Y is X * 3.
| divv(X, Y)  :- n(X), Y is X / 3.
| modd(X, Y)  :- n(X), Y is X mod 3.
| dz(X, Y)    :- n(X), Y is X / 0.
| mz(X, Y)    :- n(X), Y is X mod 0.
| prec(X, Y)  :- n(X), Y is X + 2 * 3.
| paren(X, Y) :- n(X), Y is (X + 2) * 3.
? plus(X, Y)  -> ["X = -7, Y = -6","X = 0, Y = 1","X = 10, Y = 11","X = 7, Y = 8"]
? minus(X, Y) -> ["X = -7, Y = 7","X = 0, Y = 0","X = 10, Y = -10","X = 7, Y = -7"]
? times(X, Y) -> ["X = -7, Y = -21","X = 0, Y = 0","X = 10, Y = 30","X = 7, Y = 21"]
? divv(X, Y)  -> ["X = -7, Y = -2","X = 0, Y = 0","X = 10, Y = 3","X = 7, Y = 2"]
? modd(X, Y)  -> ["X = -7, Y = -1","X = 0, Y = 0","X = 10, Y = 1","X = 7, Y = 1"]
? dz(X, Y)    -> []
? mz(X, Y)    -> []
? prec(X, Y)  -> ["X = -7, Y = -1","X = 0, Y = 6","X = 10, Y = 16","X = 7, Y = 13"]
? paren(X, Y) -> ["X = -7, Y = -15","X = 0, Y = 6","X = 10, Y = 36","X = 7, Y = 27"]
```

Читается так: деление усекает **к нулю** (`-7 / 3 = -2`, не `-3`), `mod` берёт знак делимого
(`-7 mod 3 = -1`), деление и остаток на ноль дают не ошибку, а **тихий провал посылки** (пусто),
`*` и `/` крепче `+` и `-`, скобки работают. Нецелый операнд — тоже тихий провал, не ошибка:

```
| p(a). p(1).
| b(X, Y) :- p(X), Y is X + 1.
? b(X, Y) -> ["X = 1, Y = 2"]
```

Чего в v0 **нет** и что, стало быть, реализовывать не нужно:

```
| p(1.5).                        load ok=false diagnostics=["line 1: expected ')', got '.'"]
| q(X, Y) :- n(X), Y is -X.      load ok=false diagnostics=["line 2: expected a term, got '-'"]
```

Плавающей точки в синтаксисе v0 нет вообще; унарный минус применим только к литералу
(`parser.ts:104-108`), не к переменной. `*` и `/` в сьюте не встречаются ни разу, но синтаксис их
принимает (`mulExpr`, `parser.ts:140-148`), и заводить их надо вместе с остальными — иначе получится
тихо-пустое отношение из пункта 3.

Форма для транслятора: `is` переписывается в трёхместный билтин-производитель (`Y` — выход), а
дерево выражения разворачивается во временные переменные — тот же режим, что у `concat/3`, который
уже доказан выше.

### 6. `=` — расщепляется надвое

**`=`, где одна сторона связана** (фильтр `X = a` или биндинг `Y = X`) — `translate-with-rewrite`.
В сьюте таких **0**, но конструкция настоящая:

```
| p(a). p(b).
| only(X) :- p(X), X = a.
| bind(X, Y) :- p(X), Y = X.
? only(X)    -> ["X = a"]
? bind(X, Y) -> ["X = a, Y = a","X = b, Y = b"]
```

Билтина `eq` в RFDB нет — и, что важнее, попытка его выпустить не упадёт, а даст пусто:

```
| q(X) :- p(X), eq(X, "a").
| p("a"). p("b").
-> 0 rows
```

Правильное переписывание — подстановка (константу подставить в литерал, синоним переменной
устранить); равенство связанных переменных выражается структурным повтором переменной, что RFDB
принимает:

```
| q(X) :- p(X), r(X).
| p("a"). p("b"). r("a").
-> {"X":"a"}
```

**`=`, где обе стороны несвязаны** — идиома `X = X`, 3 кейса (`p1-functor-append` кл. 1,
`p4-tm` кл. 29-31, `p4-tm-diverge`) — **out-of-scope для этого лейна**. Обоснование конкретное, а не
«длинный хвост»: это вообще не диалектное различие. `classify()`
(`vendor/rofl-v0/src/engine.ts:145-148`) на `=` с двумя несвязанными сторонами ставит `safe = false`,
и правило становится demand-backed, то есть отвечает сверху вниз. Расширение такого отношения
**открыто** — его нельзя материализовать никаким локальным переписыванием:

```
| p(a). p(b).
| idty(X, X) :- X = X.
| r(X, Y) :- p(X), idty(X, Y).
? r(X, Y)    -> ["X = a, Y = a","X = b, Y = b"]
? idty(A, B) -> ["A = ?B, B = ?B","A = a, B = a","A = b, B = b"]
```

Строка `A = ?B, B = ?B` — это и есть demand-ответ. Замена `X = X` на положительную посылку
downstream-ответ не меняет, но само отношение обедняет:

```
| p(a). p(b).
| idty(X, X) :- p(X).
| r(X, Y) :- p(X), idty(X, Y).
? r(X, Y)    -> ["X = a, Y = a","X = b, Y = b"]     <- то же
? idty(A, B) -> ["A = a, B = a","A = b, B = b"]     <- открытой строки нет
```

А «просто выкинуть `=`» нельзя и в самом v0 — безтелное неземлённое предложение он отвергает:

```
| idty(X, X).
load ok=false diagnostics=["fact idty[main](?X,?X)@now: must be ground"]
```

В `tm.rofl` это ещё жёстче: `H2 = H2` — **единственный** элемент тела, и ответ рождается целиком
top-down:

```
| move(r, L, W, cons(H2, R2), tape(cons(W, L), H2, R2)) :- H2 = H2.
| move(r, L, W, nil, tape(cons(W, L), 0, nil)) :- W = W.
? move(r, nil, 1, nil, T) -> ["T = tape(cons(1,nil),0,nil)"]
```

Работа тут ограниченная и понятная, но она принадлежит лейну `missing:demand-mode` (и `p4-tm`
дополнительно упирается в `missing:compound-terms`). Стоимость: **A1** (`p4-tm`, `p4-tm-diverge`).
Конкретное действие для этого лейна: транслятор сейчас выдаёт на `X = X` код
`dialect:untranslatable` — это неверный код, его надо переклассифицировать в `missing:demand-mode`,
иначе лейн навсегда останется «незакрываемым» из-за чужой работы.

### 7. Одно отношение в двух арностях — `translate-with-rewrite` (0 кейсов)

В v0 арность не входит в идентичность отношения: ключ факта —
`${rel}[${persp}](${args.map(canonTerm).join(',')})` (`vendor/rofl-v0/src/store.ts:25-27`), индекс —
`rel -> persp -> keys` (`store.ts:38`). Поэтому:

```
| p(a). p(a, b).
| q(X) :- p(X).
| r(X, Y) :- p(X, Y).
? p(X)    -> ["X = a"]
? p(X, Y) -> ["X = a, Y = b"]
factKeys(p) = ["p[main](a)","p[main](a,b)"]
```

RFDB — фиксированной арности:

```
| q(X) :- p(X).
| p("a"). p("a", "b").
!! ERROR: derive engine error [E-BIND-002]: binding: E-BIND-002: predicate 'p' already bound at arity 1 but a clause binds it at arity 2
```

Переписывание — имя на арность; проверено, что это снимает конфликт:

```
| xq(X) :- u_p_1(X).
| u_p_1("a"). u_p_2("a", "b").
-> {"X":"a"}
```

### 8. Несвязное тело — `translate-with-rewrite` (4 кейса)

Текст отказа (`translate.ts:277`) верен по факту, но не называет причину. Она в другом: во всех
четырёх кейсах общая переменная существует, просто она сидит в **слоте перспективы**, а транслятор
перспективу отбрасывает. Проверено на клаузе 31 из `BOOT+SENSORS`:

```
| reading[s1](t1, v20).
| reading[s2](t1, v21).
| corroborated[trust](s1).
| temp[verified](T, V) :- reading[S](T, V), corroborated[trust](S).
? temp[verified](T, V) -> ["T = t1, V = v20"]
```

Если перспективу протащить лишней колонкой — RFDB принимает и даёт тот же ответ:

```
| xtemp(T, V) :- u_reading(S, T, V), u_corroborated("trust", S).
| u_reading("s1", "t1", "v20"). u_reading("s2", "t1", "v21").
| u_corroborated("trust", "s1").
-> {"T":"t1","V":"v20"}
```

Если отбросить — получается настоящий кросс-джойн, и движок прав, что ругается:

```
| xtemp(T, V) :- u_reading(T, V), u_corroborated(S).
!! ERROR: derive engine error [E-PLAN-003]: plan: E-PLAN-003 (xtemp): cross-join: literal `u_corroborated` shares no bound variable with the preceding body
```

Отдельно: **честный** кросс-джойн в v0 законен —

```
| q(a). q(b). r(x). r(y).
| cross(X, Y) :- q(X), r(Y).
? cross(X, Y) -> ["X = a, Y = x","X = a, Y = y","X = b, Y = x","X = b, Y = y"]
```

— и для него нужен мост-предикат; проверено, что мост снимает `E-PLAN-003`:

```
| xcross(X, Y) :- u_q(X), u_univ(X, Y), u_r(Y).
-> {"X":"a","Y":"x"} {"X":"a","Y":"y"} {"X":"b","Y":"x"} {"Y":"y","X":"b"}
```

Так что решение двойное: перспективу протаскивать колонкой (это снимает все 4 кейса), а честный
кросс-джойн — через мост. Первое зависит от лейна `missing:perspectives`, второе — нет.

### 9. Флаг `naive` — `translate-with-rewrite` (1 кейс)

Единственный кейс, где диалект — **единственный** блокер (`p1-tc-naive`). Адаптер сейчас просто
бросает (`adapter.ts:33-39`). Но в v0 это внутренний переключатель стратегии (`engine.ts:48,62,252`),
и на той самой программе, которую гоняет сценарий, множества фактов **побайтово совпадают**:

```
edge(a, b). edge(b, c). edge(c, d).
path(X, Y) :- edge(X, Y).
path(X, Y) :- edge(X, Z), path(Z, Y).

seminaive domainFactSet = ["edge(a,b)","edge(b,c)","edge(c,d)","path(a,b)","path(a,c)","path(a,d)","path(b,c)","path(b,d)","path(c,d)"]
naive     domainFactSet = ["edge(a,b)","edge(b,c)","edge(c,d)","path(a,b)","path(a,c)","path(a,d)","path(b,c)","path(b,d)","path(c,d)"]
IDENTICAL = true
seminaive ? path(X,Y) rows = 6 ; naive = 6
naive holds(path(a,d)) = true ; holds(path(d,a)) = false
```

Все проверки сценария — наблюдаемые на множестве фактов. Значит, флаг надо **принимать и
игнорировать**, а не отказывать. И этот же прогон на RFDB (с префиксом `u_`, иначе `edge/2`
конфликтует с базовым `edge/3` — `E-CAT-002`) даёт те же 6 строк:

```
| u_path(X, Y) :- u_edge(X, Y).
| u_path(X, Y) :- u_edge(X, Z), u_path(Z, Y).
| u_edge("a", "b"). u_edge("b", "c"). u_edge("c", "d").
-> {"X":"a","Y":"b"} {"Y":"c","X":"a"} {"X":"a","Y":"d"} {"X":"b","Y":"c"} {"Y":"d","X":"b"} {"X":"c","Y":"d"}
```

## Что переводится молча — и переводится верно

Пройденный в обратную сторону синтаксис v0 дал четыре конструкции, которые транслятор пропускает без
отказа. Все четыре проверены на эквивалентность, а не приняты на веру:

- **одно отношение и как факт, и как голова правила** — расширение есть объединение. v0:
  `p(a). p(X) :- q(X). q(b).` → `? p(X) -> ["X = a","X = b"]`, `factKeys(p) = ["p[main](a)","p[main](b)"]`.
  RFDB: `xdump(X) :- p(X). p("a"). p(X) :- q(X). q("b").` → `{"X":"a"}`, `{"X":"b"}`.
- **рекурсия** — 6 строк с обеих сторон (прогон выше).
- **отрицание** — v0 `not`, RFDB `\+`: `o(X) :- p(X), \+ c(X). p("a"). p("b"). c("a").` → `{"X":"b"}`.
- **wildcard `_`** — `q(X) :- p(X, _). p("a","z"). p("b","z").` → `{"X":"a"}`, `{"X":"b"}`.

Плюс сам префикс `u_` (`translate.ts`, `PFX`) — не косметика, а необходимость: без него `edge` и
`path` сталкиваются с базовыми отношениями RFDB (`E-CAT-002`).

## Смежная находка: две over-refusals, которые держат boot.rofl

Не диалектный лейн, но прямо на пути «boot.rofl транслируется», поэтому фиксирую здесь.
`boot.rofl` несёт четыре отказа `missing:demand-mode`, и три из них неверны:

- `translate.ts:232` отвергает **константу в голове** (16 RED-кейсов) — RFDB её принимает:
  `xtop(A, B) :- u_h(A, B). u_h(K, "lit") :- u_p(K). u_p("k1").` → `{"A":"k1","B":"lit"}`.
  Более того, ровно базовая клауза boot.rofl:19 работает как есть:
  `xtop(R, N) :- u_stratum(R, N). u_stratum(R, 0) :- u_edb(R). u_edb("imports"). u_edb("concludes").`
  → `{"R":"concludes","N":"~int:0"}`, `{"R":"imports","N":"~int:0"}`.
- `translate.ts:235` отвергает **повторную переменную в голове** (16 RED-кейсов; в boot.rofl это
  `sees(P, P) :- perspective(P).`, строка 7) — RFDB её принимает:
  `xq(X, X) :- u_p(X). u_p("a").` → `{"X":"a"}`.
- `translate.ts:239` отвергает `N` в голове `boot.rofl:20` как несвязанную (18 RED-кейсов) — но `N`
  связывается билтином `is`. Этот отказ — **следствие** диалектного, а не самостоятельный: он
  исчезнет вместе с арифметикой.

Четвёртый отказ (`unsafe negation`, `translate.ts:246`, 15 RED-кейсов, клауза `leak[audit]` на
`boot.rofl:31`)
настоящий: RFDB действительно отвергает —
`xq(X) :- u_p(X), \+ u_c(X, Y).` → `E-PLAN-002 (xq): cannot order bound-first: no feasible binding for ["u_c"]`.
Заодно `translate.ts:239` в текущем виде ложно-положителен ещё и потому, что не считает связанными
переменные, идущие из головы через `Term::Lit`-константу — но это уже вопрос к владельцу того лейна.

| решение | конструкций | суть |
|---|---:|---|
| translate-as-is | 8 | целые (в литерале и в билтине), `!=`, `<`, `<=`, `>`, `>=` — RFDB уже умеет, нужен только декодер тегов в харнессе |
