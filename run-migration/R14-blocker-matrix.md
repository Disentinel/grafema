## Зачем понадобился повторный замер

R13 был измерен **до** того, как в движок приехал единый wire-кодек значений Datalog
(коммит `0e6271c9`). Отчёт R13 сделан на **debug**-бинаре, собранном на `bc3db6c1`
(= `0e6271c9~2`) — то есть буквально на до-кодековом движке. Поэтому все выводы R13 про
«числовые константы» были сделаны на движке, который физически не мог отличить целое от
идентификатора узла **на проводе**. Числа надо было переснять, а не пересчитать.

Метод восстановления полной матрицы повторяет R13: `translate()`
(`packages/rofl-conformance/src/translate.ts:148-200`) идёт по фиксированным фазам и возвращает
управление на **первом же** совпадении, поэтому прогон сьюта даёт ровно ОДИН блокер на кейс.
Проба зеркалит все точки отказа адаптера (`packages/rofl-conformance/src/adapter.ts`), но не
выходит из сценария, а **собирает все** блокеры, делегируя семантику `OracleEngine`, — так каждый
сценарий доигрывается до конца.

Самопроверка пробы (тот же гейт, что и в R13): у всех GREEN-кейсов список блокеров обязан быть
пуст, у всех RED — обязан содержать тот код, который реально вернул сьют. **30/30 сходятся,
0 расхождений.** У всех 5 GREEN список пуст.

## Целочисленные константы: измерено на движке, а не прочитано в коде

Вопрос раунда: различает ли **поверхность** derive-движка целое `1` и идентификатор узла `1` — в
теле правила, в голове правила и как аргумент сохранённого факта? Ответ получен экспериментом
(`/tmp/int-probe.ts`, `/tmp/int-probe2.ts`, релизный бинарь `09dbe1cf`, живой сервер).

**Различает во всех трёх позициях, плюс в джойне, в builtin-е и в explain.**

Аргумент сохранённого факта:

```
p("k_bare_int", 1). p("k_quoted", "1"). p("k_float", 1.5).
p("k_big", 295147905179352825856). p("k_neg", -7).
xout(K, V) :- p(K, V).
  -> {"K":"k_bare_int","V":"~int:1"}
  -> {"K":"k_quoted",  "V":"1"}
  -> {"K":"k_float",   "V":"~float:1.5"}
  -> {"K":"k_big",     "V":"~big:295147905179352825856"}
  -> {"K":"k_neg",     "V":"~int:-7"}
```

Тело правила (фильтр по константе):

```
q(K) :- p(K, 1).    -> {"K":"k_bare_int"}   (только целое)
q(K) :- p(K, "1").  -> {"K":"k_quoted"}     (только строка/id)
```

Голова правила (наблюдаем на шаг ниже):

```
h(K, 1)   :- p(K,_).  top(A,B) :- h(A,B).  -> {"A":"k1","B":"~int:1"}
h(K, "1") :- p(K,_).  top(A,B) :- h(A,B).  -> {"A":"k1","B":"1"}
```

Джойн по целочисленной колонке не смешивает стороны:

```
r(K1,K2) :- p(K1,V), p2(V,K2).
p("a",1). p("b","1"). p2(1,"int-side"). p2("1","id-side").
  -> {"K1":"a","K2":"int-side"}   -> {"K1":"b","K2":"id-side"}
```

Builtin со сравнением: `big(X) :- n(X), gt(X, 8).  n(7). n(10).` → `{"X":"~int:10"}`.

Адресация через explain (то есть целое доезжает и до ключей протокола):

```
explainDatalogFact(src,'q',['k_bare_int','~int:1'])  -> witness (ruleAstHash + body)
explainDatalogFact(src,'q',['k_bare_int','1'])       -> null      (это узел id 1, не совпадает)
explainDatalogFact(src,'q',['k_quoted','1'])         -> witness
```

И, наконец, ровно та форма, что стоит в `boot.rofl`:

```
stratum(Rel, 0) :- edb(Rel).   edb("has_premise"). edb("concludes").
  -> [{"Rel":"concludes"},{"Rel":"has_premise"}]
```

**Ни один слой движка не отказывает.** Парсер:
`packages/rfdb-server/src/datalog/parser.rs:146-223` — голая цифра идёт в `parse_number()` и даёт
`Term::Lit(Value::Int/Float/Big)`, а не строковую константу и не id. Тип:
`packages/rfdb-server/src/datalog/types.rs:12-14` — «carrying its `Value` directly so it is NOT
conflated with a string const or a node id (spec §5)». Планировщик:
`packages/rfdb-server/src/derive/plan.rs:145` — `Term::Const(_) | Term::Lit(_) | Term::Wildcard`
одинаково считаются связанными. Исполнитель:
`packages/rfdb-server/src/derive/exec.rs:3623-3624` — `Term::Lit(v) => out.push(v.clone())` против
`Term::Const(s) => out.push(Value::from_term_const(s))`. Хранилище:
`packages/rfdb-server/src/derive/value.rs` — теговое кодирование `fact_id` (TAG_ID … TAG_TERM) с
golden-тестами на побайтовую стабильность.

Отказывает **только транслятор харнесса**:
`packages/rofl-conformance/src/translate.ts:115-121`. И его обоснование протухло: он ссылается на
`rfdb_server.rs:3205-3210` как на место, где «all-digit strings re-type to `Value::Id`», а на HEAD
по этим строкам лежит doc-комментарий делегата кодека
(`packages/rfdb-server/src/bin/rfdb_server.rs:3202-3213`), и сам делегат —
`fn wire_string_to_value(s) { rfdb::datalog::wire_string_to_value(s) }`.

(Отчёт R13 сохранён в `/tmp/R13-conformance-report.json` и сдиффен со свежим по каждому сценарию:
`verdict/reason diffs vs R13: 0`. Движок при этом сменился: R13 — debug на `bc3db6c1`, R14 —
release на `09dbe1cf`.)

**Что реально изменил wire-кодек и почему это не сдвинуло вердикты.** Типизированный литерал
`Term::Lit` существовал ещё ДО кодека — он приехал коммитом `43431ddd` («Datalog v2 — typed numeric
literals (Int/Float), spec §5»); `git show 0e6271c9~1:packages/rfdb-server/src/datalog/parser.rs`
уже содержит `Term::Lit`, а `git show bc3db6c1:packages/rfdb-server/src/datalog/types.rs` уже
содержит `Lit(crate::datalog::eval::Value)`. То есть **поверхность** различала целое и id уже на
том sha, на котором мерили R13. Кодек `0e6271c9` починил не поверхность, а **транспорт**:
`git show 0e6271c9~1:packages/rfdb-server/src/graph/engine_v2.rs` показывает до-кодековый
рендерер, где `Value::Id(id) => id.to_string()` и `Value::Int(i) => i.to_string()` — байт в байт
одно и то же. До кодека целое было **ненаблюдаемо на проводе**; после — адресуемо (`~int:1` против
`1`, и `explainDatalogFact` отвечает `null` там, где раньше не смог бы различить).

**Единственная содержательная новость раунда:** подлиния «целочисленные константы» (17 из 25 RED)
**больше не является пробелом движка** — это остаточный отказ харнесса с протухшей ссылкой.

**И этого недостаточно, чтобы что-то сдвинуть — тоже измерено.** Если снять только
«целочисленные константы» → закрывается **0 из 25**. Если снять «целочисленные константы» +
builtins → **0 из 25**. Если снять ВСЕ подлинии `dialect:untranslatable` → **1 из 25** (это
`p1-tc-naive`, у которого единственный блокер — подлиния `naive-mode`, к числам отношения не
имеющая). Причина видна прямо в матрице: `dialect:untranslatable` — ЕДИНСТВЕННЫЙ блокер ровно у
одного кейса, а во всех остальных 18 он идёт в компании `demand-mode`, `rules-as-data` и
`perspectives`.

## Что из этого следует для порядка работ

1. Приоритеты R13 остаются в силе без изменений: колонка «встречается» + кривая жадного закрытия,
   а не «первый блокер».
2. Ближайшая цель — по-прежнему **ядро из четырёх линий**, а не отдельная линия: до него кривая
   плоская (3 → 4 → 5), на нём прыгает до 11.
3. `boot.rofl` — по-прежнему узкое место всей четвёрки, и правильная единица работы —
   «сделать `boot.rofl` переводимым».
4. Внутри этой единицы работы одна подлиния из пяти теперь стоит **дёшево**: целочисленные
   константы (17 из 25) требуют не работы по движку, а снятия устаревшей проверки в
   `translate.ts:115-121` и обновления ссылки. Само по себе это даёт 0 закрытых кейсов, поэтому
   делать это надо **внутри** работы по `boot.rofl`, а не как отдельный шаг, — иначе получится
   изменение с нулевым измеримым эффектом.
5. Чего в движке действительно нет и что придётся добавлять для `boot.rofl`: арифметического
   builtin-а. `add(X, 1, Y)` даёт 0 строк, и в реестре
   (`packages/rfdb-server/src/derive/builtin.rs:1358-1568`, «this is the sole registration point»)
   арифметики нет вообще — 29 имён, только
   сравнения и строковые операции. `boot.rofl` содержит `N is M + 1`.
